# 未来前台 GEO 证据增长系统客户交付方案

版本：GeoEvidence Studio v0.1.0

日期：2026-10-18

## 方案定位

以 GeoEvidence Studio v0.1.0 为单客户试点系统：

- 100 条未来前台问题；
- DeepSeek Search + Chat 真实采集；
- 回答、引用、模型和证据哈希；
- 品牌提及、引用、首推和 SOV；
- 行业负面与品牌负面分离；
- 10 类文章草案；
- 本地和 webhook 发布回执；
- WorkLoom GEO 工具桥；
- 中文看板和真机验证。

当前不是完整四平台生产平台，豆包、元宝、真实客户 CMS 和第三方信源仍需逐阶段接入。

## 基础业务闭环

```text
客户确认事实
  → 确认 100 条问题
  → 系统采集 AI 答案
  → 保存答案与引用证据
  → 计算指标与负面事件
  → 生成内容草案
  → 人工审核和发布
  → 回填真实 URL
  → 同题复测
  → 周报和月报
```

## 人机分工

| 客户业务负责人 | 系统 |
|---|---|
| 确认真实企业、产品、价格、资质和售后 | 结构化事实和冲突检查 |
| 确认问题和优先级 | 生成、分类和版本化问题集 |
| 授权平台和发布账号 | 采集、证据保存和发布回执 |
| 判断负面事件责任和纠偏动作 | 区分行业负面与品牌负面并告警 |
| 审核公开发布内容 | 生成文章草案、保存内容 Hash |
| 每月决定经营重点 | 提供趋势、引用机会和复测 |

## 100 条问题结构

| 类别 | 数量 |
|---|---:|
| 品牌确认 | 20 |
| 品类选购 | 25 |
| 使用场景 | 25 |
| 竞品对比 | 15 |
| 负面与风险 | 15 |

所有问题当前状态为 `client_confirmation_required`，客户确认后才能作为正式基线。

## 必须确认的四本字典

1. 法定实体与品牌别名。
2. 官方域名与可信页面。
3. 竞品名单与产品关系。
4. 负面风险源和安全高风险词。

缺字典时对应指标为 N/A，不能填 0 或推断。

## 当前指标

- 采集成功率。
- 证据覆盖率。
- 品牌提及率。
- 首推率。
- 有引用回答率。
- 自有信源引用率。
- SOV。
- 品牌负面提及率。
- 负面曝光率。
- 负面引用率。
- 品牌安全率。

首推率当前是 v0 启发式；未配置官网域名或竞品时，自有引用率和 SOV 为 N/A。

## 分阶段交付

### 阶段 0：客户数据冻结，2–3 个工作日

- 营业执照和法定主体。
- 官网域名。
- 产品型号和事实边界。
- 竞品和负面来源。
- 100 条问题确认。
- 发布账号和审批人。

### 阶段 1：v0.1.0 试点，1–2 周

- DeepSeek 真实采集 20–30 条。
- 其他平台人工导入。
- 首份能见度和品牌负面基线。
- 10 篇文章草案。
- 3–5 篇客户审核稿。
- 一条官网/人工发布回执。

### 阶段 2：多平台扩展，2–3 周

- 豆包。
- 元宝。
- 按目标增加 Kimi 或通义。
- 截图/DOM 存证。
- 定时采集和负面闭环。

### 阶段 3：生产化，3–4 周

- PostgreSQL 和 RLS。
- WorkLoom 审批与内容 Hash 绑定。
- 客户 CMS 和第三方信源。
- 趋势、来源机会和内容归因。
- 周报、月报和长期运营。

## 验收

- 100 条问题客户确认率 100%。
- MVP 至少 3 个平台。
- 成功样本率 ≥95%。
- 每条成功样本有原始答案和证据哈希。
- 浏览器采集样本有截图/DOM。
- 行业负面不得计作品牌负面。
- 未确认事实不得公开发布。
- 发布后有 URL、平台 ID、内容 Hash 和回执。

## 不承诺

- 不保证 AI 必须提及品牌。
- 不保证品牌永不出现负面。
- 不自动删除第三方负面页面。
- 当前未接通全部四个平台。
- 当前未接通知乎、公众号、百家号自动发布。
